# DrawSomething packaged implementation boundary

This pass examines the caller-supplied Soul international 2.78.0 XAPK only. It performs no target execution, login, server requests or feature enabling. Carrier identity and inventories are retained in `ui-inventory.json`; focused code references in `ui-selected-methods.json`.

## Findings

**Observed:** Exact DrawSomething/draw-guess/Chinese naming markers occur in two DEX members: `classes2.dex` contains the `cn.soulapp.imlib.msg.chat.GameMsg` adapters; `classes8.dex` contains generated `com.soul.game.protos` declarations and embedded protobuf descriptor strings. The other seven DEX string pools have no matching marker under the documented regular expression. This is a bounded name search, not proof that obfuscated implementations are absent.

**Observed:** `GameMsg` is a `TopChatMsg` subtype, with `id`, `gameId`, `phase`, `type`, `extMap`, `inviteGameMsg`, and `gameoverGameMsg` fields. Its nested invitation object has inviter/invitee/extMap. Its nested DrawSomething gameover object has a list of answer results; each result has question/questionDesc/answer/answerDesc/right/ts/extMap. There are no ready/play fields in this adapter class.

**Observed:** `classes2.dex` `GameMsg.convert`, method index 6040, code offset 1410892, has complete standard-opcode traversal. Invocations include `CommandMessage.getMsgCommand` at DEX file offset 1410908, `MsgCommand.getGameMessage` at 1410916, `GameMessage.getGameId` at 1410946, `getPhaseValue` at 1410958; the gameover path references `getDrawSomethingGameoverGameMessage` at 1411036 and `AnswerResults.getAnswerResultsList` at 1411052. The invitation path references `getInviteGameMessage` at 1411136, `getInvitee` at 1411144 and `getInviter` at 1411156. All offsets refer to the original DEX byte sequence, not APK ZIP offsets. Control-flow/register interpretation is separate from invocation presence.

**Derivation:** The shipped IM library explicitly understands drawing-game invitation and postgame summary messages, so this is stronger than a lone unused protocol enum. This does not establish a playable screen or active game-session engine. Parent investigation's universal incoming-reference scan should be used to establish how the generic chat pipeline consumes `GameMsg`.

**Observed:** All three APK ZIP member-name inventories show no DrawSomething/draw-guess-specific file. Existing compiled resource pools cover 32,057 base-resource strings and 75 mdpi strings; no exact matching game markers are present. The retained `libapp.so` ASCII inventory covers 18,776 strings and has no marker. A fresh scan of printable ASCII sequences in all 39 packaged native `.so` libraries likewise found none. See per-library digests in the JSON.

**Observed:** Recovered Flutter library/class inventories have no named DrawSomething/draw-guess library/class. Flutter material navigation-drawer names are unrelated. This AOT recovery previously carried a snapshot-profile limitation; it does not establish complete semantic coverage of Dart native code.

## False positives to exclude

- `cn.jarlen.photoedit.scrawl.DrawingBoardView` extends Android `View` and exposes `getDrawBitmap`, `setBackgroundBitmap`, `setBrushBitmap`, `setPaintColor`, `setStampBitmaps`; it belongs to photo-edit/scrawl code. Its name alone is not drawing-game evidence. Focused method references are retained alongside GameMsg for verification.
- `com.airbnb.lottie.animation.content.DrawingContent` is animation rendering; RecyclerView drawing-order and Flutter drawer classes are framework code.
- Shipped audio-call rule text mentions “dice roller, figure-guessing games”; this is not an explicit DrawSomething marker. The package separately contains `FINGER_GUESS`/rock-paper-scissors protocols.
- `com.yw.game.floatmenu` supplies generic floating-menu controls; a `game` namespace does not link it to this game.

## Still unknown

No question bank, canvas stroke serialization, drawing-session screen, gameplay route, feature flag specifically naming DrawSomething, score algorithm, server session timing, or voice-room integration was identified in this inventory. HTTP/downloaded H5 content and obfuscated business code could provide some of those layers. Static negative marker searches cannot exclude them. Avoid inventing a coordinate format or treating `extMap` as an established stroke channel.

Those indexes are generated by the previous package pass and retain DEX digests; the fresh native scan reads the original XAPK directly. `ui-selected-methods.json` was produced using the format parser and standard-width reference decoder in `extract_gameplay_schemas.py`, selecting only GameMsg and photoedit/scrawl declarations. Every selected method records complete/incomplete traversal status. This focused decoder omits field/type references and does not decompile source or reconstruct register flow.
